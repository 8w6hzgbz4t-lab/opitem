# First release feedback plan

Use Creator Dashboard analytics and a small invited test group first. No external tracking endpoint or automatic messages were added.

1. Observe the funnel: join → finish guide → choose starter → reserve/buy → pick up → deliver → collect earnings → upgrade. Record where first-time players stop and how often first purchases are lost.
2. Track technical health before monetization: failed/locked loads, save/transfer latency, storage budget, deferred receipt delivery, unknown product IDs, FPS/memory and disconnects during carries. Fix data loss, duplicate grants and repeated errors before growth work.
3. During two-player and eight-player sessions, count successful deliveries, failed carries, theft recovery, shield blocks and repeated control mistakes. Ask testers whether selecting versus activating powers is clear and whether losses feel understandable.
4. Compare first-session completion, session length and return visits after each small update. Do not change rarity, power balance, pricing and tutorial simultaneously; keep a change log so feedback can identify causes.
5. Collect brief feedback manually through your chosen moderated channel. Avoid collecting personal information. Review concerns about unfair powers, confusing purchase rewards, loud sounds, clipped Index models or slow saves.

If adding custom Roblox AnalyticsService events later, send them only from trusted server outcomes and test the current API/consent/platform requirements first. Player counts, engagement and revenue are not guaranteed by completing the code.
